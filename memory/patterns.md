# Patterns

> The living memory. Agents read this at start, update it at end. This file is why week 10 beats week 1.

## What works

- **Rule 7 is beaten by deletion, not rewriting.** First draft to clear rule 7 under an independent gate (Base1 / dev-accelerator, 2026-07-28). The fix was cutting the third list item outright — hosting, from "full-stack / database and authentication / hosting" — not rephrasing the cadence. A tricolon split across sentence boundaries still reads as a tricolon; a two-item list does not. Cut the beat, don't move it.
- **Name the sourced action, not the implied one.** Base1 rev 2 (2026-07-28) replaced "Bring it a real project and judge the first scaffold you get" — which implied a capability the source does not carry — with "Open the AI chat and select it", the verbatim sourced action. Copy that quotes the mechanism survives rule 4 untouched and reads better to dev-accelerator than capability language does. When a claim is barred, look for the smaller true action next to it.
- **First content to pass an independent gate: `content/base1-dev-accelerator/drafts-rev2.md` — 9.0, landing page, dev-accelerator, 2026-07-28.** Cost: three gates and one substrate fix. The substrate fix (one verified source line) was worth more than either revision round.
- Everything a writer controls can score clean while the piece still fails: same run scored 8.5 with rules 1,2,3,5,6,7,8 all passing. Prior "still empty" note stands on its own point — the earlier "9.5" here was self-scored by the same context that wrote the draft, and self-review inflates by ~4 points. Do not record a win the writer graded itself.

## What doesn't

- **Rule 7 is the dominant failure mode: 3 of 3 independent drafts tripped it.** Rule-of-three lists ("Stripe, Slack, a spreadsheet"), and the literal banned "That's not X — that's Y" framing. Writers reach for the tricolon by default; it must be checked before submitting, not after.
- "Last month X. Tonight Y." temporal-antithesis hooks (rule 7 variant). 2nd occurrence of the rule-7 family — the family is already a numbered rule, so it needs sharper enforcement in writer.md, not a new rule.
- **The brief mandated a CTA the source cannot support (Base1 / dev-accelerator, 2026-07-28).** `data/source-base1.md` establishes that Base1 exists, is in-house, is trained on real building patterns, and shipped 2026-06-29 — nothing about what it *does* or whether a builder can reach it. The brief's CTA ("Try Base1 on your next build") asserts availability and function, so rule 4 kills the one line rule 8 requires. Unfixable by the writer. **Check CTA-viability against the source file at brief time, not at gate time** — one line of source work before writing saves a full revision round.
- **Publishing order is ingest → build → deploy, and it is not interchangeable (2026-07-28).** `build:site` reads the DEPLOY TARGET's board endpoint, not the local store, so a card that exists only locally produces a site whose board links to routes the build never wrote. Push the card to the hosted store first, confirm `/functions/board` returns it, then build, then deploy. Ingest is itself a publish — the board is public and reads live, so the copy is visible the moment the card lands, before any page ships. Get text approval before the ingest, not before the deploy.
- **Ask a gate to rule on the thing you are unsure about, by name.** Both guardians produced their most useful findings on questions put to them explicitly — the CTA-viability ruling that sent the Base1 campaign back to the substrate, and the licence gap in the embedded font. A gate handed "score this" returns a score; a gate handed a specific doubt returns a decision you can act on.
- **`verify:page` PASSing is not evidence the page looks right (Base1, 2026-07-28).** The rendered page passed every deterministic check and was then rejected 7.5 by the design gate: `src/render/page.ts` emits no `@font-face` and no font `<link>` at all, and its `h1` stack is `"Dazzed", system-ui` — Geist missing entirely, so the headline falls back to the visitor's OS face while the body renders in Geist. The roles invert. `verify:page` covers structure, tracking, mobile and the marker; it does not cover typography, which is exactly the gap DESIGN.md's "trust that a webfont loaded — verify it" names. Free checks narrow the guardian's job, they never replace it.
- **`attributes.display_font` is scoped to the card, not per artifact.** It recorded `Geist` (true of `card.png`, which really embeds the bytes) while the page's headline used neither Dazzed nor Geist. The board under-reports fallback depth for the page half of a card.
- **Candidate rule (1st recorded occurrence — promote on the 2nd): audience language files are targeting data, never sourcing.** All three Base1 angles reached for "you own what comes back" / "live and yours", pulled from `dev-accelerator`'s "own the code" in `brand/audiences.md`. That file says what a segment wants to hear; it is not a facts file. Counted as ONE occurrence — three drafts from one writer context is one failure, not three.
- **The rule 3 / rule 4 squeeze (structural, not a writing mistake).** Rule 3 demands a concrete reader outcome in the first line; rule 4 cuts any specific not traceable to a source. With no sourced facts file in the repo, every concrete outcome the writer invents ("chasing follow-ups", "the failed payment") is correctly killed by rule 4 — so the writer cannot satisfy 3 and 4 at once. Fix the substrate, not the writer.
